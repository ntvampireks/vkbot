# VK Bot — Диалоговый бот для сообщества VK

Простой диалоговый бот для сообщества VK, использующий LongPoll API для получения сообщений в реальном времени.

## Что нового

### Последние улучшения

- **Валидация peer_id** — проверка корректности ID получателя перед отправкой сообщения (тип, положительность, диапазон)
- **Валидация данных в БД** — проверка `user_id`, `role` и `text` при добавлении сообщений
- **Timeout для SQLite** — соединение с базой данных теперь имеет таймаут 30 секунд для предотвращения бесконечных блокировок
- **Валидация данных в БД** — проверка `user_id`, `role` и `text` при добавлении сообщений
- **Timeout для SQLite** — соединение с базой данных имеет таймаут 30 секунд для предотвращения бесконечных блокировок

## Возможности

- Обработка сообщений от пользователей в реальном времени через VK LongPoll API
- Поддержка диалогового режима с сохранением контекста и истории (настраиваемое количество сообщений)
- Простая система намерений (intent classification) по ключевым словам
- SQLite хранение с автоматическим управлением сессиями
- Расширяемая архитектура обработчиков с автоматической регистрацией
- Rate limiting для защиты от превышения лимитов VK API (~3 сообщения/сек)
- Фильтрация собственных сообщений бота и проверка упоминаний
- **Дедупликация сообщений** — предотвращение обработки дубликатов
- **Health-check сервер** — мониторинг здоровья бота (FastAPI)
- **Метрики** — сбор статистики в формате Prometheus
- **Ретраи при ошибках** — автоматическая повторная попытка отправки сообщений
- **Ротация логов** — автоматическое управление файлами логов
- **Фоновая очередь отправки** — неблокирующая отправка сообщений
- **Валидация входных данных** — проверка peer_id, user_id, role и текста сообщений

## Быстрый старт

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Настройка токена сообщества VK

#### Шаг 1: Создать приложение VK

1. Зайдите в [раздел разработчиков VK](https://dev.vk.com/)
2. Нажмите «Создать приложение»
3. Заполните:
   - **Название**: любое (например, «Мой бот»)
   - **Платформы**: выберите «Сообщества»

#### Шаг 2: Подключить API сообщества

1. Зайдите в [панель управления сообществом](https://vk.com/groups)
2. Выберите ваше сообщество
3. Перейдите в **Управление → Настройки → Работу с API**

#### Шаг 3: Создать токен доступа

1. В разделе **Работа с API** нажмите «Создать токен»
2. Выберите необходимые права:
   - `messages` — доступ к сообщениям (обязательно)
3. Скопируйте сгенерированный токен

#### Шаг 4: Включить LongPoll

1. В том же разделе **Работа с API** найдите **Long Poll API**
2. Нажмите «Подключить»
3. Запомните `server`, `key`, `v` — они понадобятся для ручного тестирования

### 3. Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```bash
cp .env.example .env
```

Заполните переменные:

```env
# Токен сообщества (из шага 3)
VK_GROUP_TOKEN=your_token_here

# ID сообщества (без минуса, например 12345678)
VK_GROUP_ID=12345678

# Имя бота для проверки упоминаний (обязательно для работы)
VK_BOT_NAME=Бот

# Опционально: настройки сервера
BOT_HOST=localhost
BOT_PORT=8000

# Опционально: таймаут сессии диалога (часы)
DIALOG_TIMEOUT_HOURS=24

# Опционально: максимум сообщений в истории диалога
MAX_HISTORY_MESSAGES=10

# Опционально: размер кэша дедупликации
DEDUP_MAX_SIZE=1000

# Опционально: TTL записей в кэше дедупликации (секунды)
DEDUP_TTL_SECONDS=300

# Опционально: путь к каталогу логов
LOG_DIR=logs

# Опционально: уровень логирования
LOG_LEVEL=DEBUG

# Опционально: задержка перед отправкой сообщения (секунды)
MESSAGE_SEND_DELAY=0.5

# Опционально: задержка между попытками повторной отправки (секунды)
MESSAGE_RETRY_DELAY=1.0

# Опционально: максимальная длина сообщения
MAX_MESSAGE_LENGTH=10000

# Опционально: защита от prompt injection
ENABLE_PROMPT_INJECTION_PROTECTION=true
```

**Как узнать ID сообщества:**

- Зайдите в управление сообществом
- URL будет вида `https://vk.com/edit?act=manage&group=12345678`
- Число после `group=` — это ID

Или в разделе **Настройки** → **Адрес страницы** — это число в конце внутреннего адреса.

### 4. Запуск бота

```bash
python -m bot.main
```

Бот начнёт слушать сообщения и отвечать на них.

### Компоненты

| Компонент | Описание |
|-----------|----------|
| `VKClient` | Клиент VK API с LongPoll, отправляет сообщения через `messages.send`, экспоненциальный backoff при ошибках, валидация peer_id |
| `EventHandler` | Обработка входящих событий, преобразует в `Message` объекты, вызывает дедупликацию и per-user rate limiting |
| `MessageDeduplicator` | Кэш для предотвращения обработки дубликатов сообщений (по `message_id`) |
| `PerUserRateLimiter` | Ограничение частоты сообщений от каждого пользователя (sliding window) |
| `DialogService` | Управление контекстом диалогов, LRU-кэш в памяти, сохраняет в SQLite |
| `IntentClassifier` | Классификация намерений по ключевым словам |
| `MessageProcessor` | Оркестратор: координирует диалог, роутинг и отправку ответа |
| `Router` | Автоматическая регистрация обработчиков, выбор по intent |
| `Handlers` | Обработчики для разных типов диалогов (автоматическая регистрация) |
| `MessageQueue` | Очередь сообщений для асинхронной отправки |
| `MessageSender` | Фоновая отправка с ретраями и rate limiting |
| `RateLimiter` | Глобальный rate limiter для VK API (~3 сообщения/сек) |
| `MetricsCollector` | Сбор метрик (счётчики, гистограммы) для мониторинга |
| `Health Server` | FastAPI сервер для health-check (/health, /ready, /metrics) |
| `DB Module` | Работа с SQLite, валидация данных, управление индексами |

### Поток обработки сообщения

1. **VKClient.run_forever()** — слушает LongPoll API
2. **EventHandler.handle_event()** — преобразует VK события в `Message` объекты:
   - Фильтрация по типу события (только MESSAGE_NEW)
   - Фильтрация сообщений от бота
   - Проверка дубликатов (MessageDeduplicator)
   - Проверка per-user лимитов (PerUserRateLimiter)
   - Валидация и санитизация текста
3. **on_message() callback** — проверка упоминания бота и вложений
4. **MessageProcessor.process()** — оркестрация обработки:
   - Получение/создание диалога через `DialogService`
   - Классификация через `IntentClassifier`
   - Выбор обработчика через `Router`
   - Вызов `Handler.handle()` для генерации ответа
   - Отправка ответа через `MessageService` → `MessageQueue`
   - Сохранение истории через `DialogService.add_message()`
5. **MessageSender** — фоновый поток отправки с ретраями и rate limiting
6. **SQLite** — persistent-хранилище для диалогов и сообщений

## Добавление нового обработчика

1. Создайте файл в `bot/handlers/`:

```python
# bot/handlers/custom_handler.py
from bot.domains.message import Message
from bot.domains.dialog import Dialog
from bot.handlers.base_handler import BaseHandler


class CustomHandler(BaseHandler):
    @property
    def intent(self) -> str:
        return 'custom'

    def handle(self, message: Message, dialog: Dialog | None) -> str:
        return 'Ответ вашего обработчика'
```

2. Новый обработчик автоматически зарегистрируется при запуске бота

3. Добавьте ключевые слова в `IntentClassifier`:

```python
# bot/services/intent_classifier.py
self.intents = {
    # ...
    'custom': ['ключевое слово 1', 'ключевое слово 2'],
}
```

## Работа с базой данных

Бот использует SQLite для хранения:

- `dialogs` — активные сессии диалогов
- `messages` — история сообщений (последние 10 на пользователя)

База создаётся автоматически при первом запуске в `storage/dialogs.db`.

### Пример SQL-запросов

```sql
-- Все активные диалоги
SELECT * FROM dialogs ORDER BY last_active DESC;

-- История сообщений пользователя
SELECT * FROM messages WHERE user_id = 12345 ORDER BY timestamp DESC;
```

## Часто задаваемые вопросы

### Как бот отличает свои сообщения от сообщений пользователей?

Бот фильтрует собственные сообщения, проверяя `out` флаг в событии VK LongPoll. Если `out=1`, сообщение отправлено ботом и игнорируется.

### Почему бот не отвечает на все сообщения?

Бот отвечает только на сообщения, где он упомянут (например, `@Бот привет`). Это предотвращает спам в общих чатах. Имя бота настраивается через `VK_BOT_NAME`.

### Как ограничить историю сообщений?

История автоматически ограничивается настройкой `MAX_HISTORY_MESSAGES` (по умолчанию 10). Настройка применяется глобально через `.env`.

### Что такое дедупликация сообщений?

Дедупликация предотвращает обработку одинаковых сообщений от VK LongPoll (иногда приходят дубликаты событий). Кэш хранит обработанные `message_id` с TTL 300 секунд по умолчанию.

### Где хранятся логи?

Логи пишутся в каталог, указанный в `LOG_DIR` (по умолчанию `logs/`). Создаются два файла:
- `logs/all.log` — все логи (DEBUG и выше)
- `logs/errors.log` — только ошибки (ERROR и выше)

Файлы логируются с ротацией (50 МБ, 5-10 резервных копий).

### Как проверить здоровье бота?

Запустите бот и обратитесь к health-endpoints:
- `GET /health` — статус здоровья и базовая статистика
- `GET /ready` — готовность к работе
- `GET /metrics` — метрики в формате Prometheus

По умолчанию сервер запущен на `http://localhost:8000`.

### Что такое фоновая очередь отправки сообщений?

Фоновая очередь позволяет отправлять сообщения без блокировки основного потока обработки. Сообщения помещаются в очередь `Queue`, а отдельный поток обрабатывает их с retry и rate limiting. Это обеспечивает:
- Неблокирующую обработку входящих сообщений
- Параллельную отправку нескольким пользователям
- Graceful shutdown (с ограниченным таймаутом 5 секунд)

### Что делать, если бот не получает сообщения?

1. Проверьте, что LongPoll подключён в настройках API
2. Убедитесь, что токен имеет права `messages`
3. Проверьте, что бот добавлен в «Служба поддержки» сообщества
